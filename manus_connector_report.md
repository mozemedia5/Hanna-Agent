## Executive summary
The current Manus session exposes **390 connector records**. These records include remote MCP connectors, direct API connectors, built-in integrations, and command-based MCP transports. The inventory is broader than the short public examples in Manus documentation, so this report treats the session inventory as the complete dated catalog for this task. It preserves separate records when one provider appears in multiple modes, such as an MCP connector and an API connector.

Manus functions as an orchestration layer rather than replacing the connected services. A connector can give Manus access to authorized data and actions, but the actual capabilities are determined by the provider’s scopes, token, workspace, plan, API quota, and the specific tools exposed by its MCP server. **Manus usage charges and third-party subscription or API charges are separate.** No provider price is presented as a fact unless it is verified from that provider’s current official pricing page; for the full inventory, the safe procurement rule is to open the provider pricing and API pages before enabling a connector.

> **Scope warning.** A complete catalog of 390 records can be exhaustive in coverage without claiming that every provider has identical permissions or pricing. Provider-specific permissions are therefore labeled as requiring review where the available Manus documentation does not publish a full scope matrix.

## How Manus connections work
Manus documentation describes four important patterns. Prebuilt MCP connectors normally use OAuth, although some require a personal API token. Built-in connectors are managed through Manus’s account authorization flow. Direct API connectors use provider credentials and inherit the provider’s API quotas and billing. Custom MCP servers and Zapier extend coverage beyond the built-in catalog. After authorization, connectors can be selected for a task; the Manus API accepts connector UUIDs and supports multiple connectors in one task. [1] [2] [3]

| Connection type | What it means | Main cost or risk to check |
|---|---|---|
| Built-in | Native Manus integration with provider-specific account authorization. | Account scopes, workspace selection, and whether actions are read-only or write-enabled. |
| Remote MCP | A provider-hosted Model Context Protocol server exposes tools to Manus. | OAuth/token scope, exposed tool permissions, provider plan, and data residency. |
| Direct API | Manus calls a provider API using a key or token. | API usage charges, rate limits, key leakage risk, and exact endpoint scopes. |
| Command MCP | MCP server uses a command or local runtime. | Runtime trust, secret storage, package provenance, and exposed commands. |

## Pricing and charging guide
There are three separate billing layers. First, Manus may charge credits or plan usage for the task itself. Second, the connected provider may charge a subscription, seat, transaction fee, API request fee, token fee, rendering credit, or data license. Third, an automation intermediary such as Zapier or Make may charge its own task or operation quota. Connecting an app does not imply that its service is free, and a provider’s free tier may still impose rate limits or restrict commercial use. Manus’s own plans and credit system should be checked in the current official plans documentation. [5]

| Situation | What may be charged | Recommended control |
|---|---|---|
| Read-only research | Manus task usage plus possible provider API/data usage. | Use read-only scopes and set provider spending limits. |
| Write-back automation | Manus task usage plus provider API/operation usage. | Require confirmation before updates, especially for CRM, finance, email, and publishing actions. |
| AI generation | Manus task usage plus model/provider tokens or credits. | Pin an approved model, monitor quotas, and review retention terms. |
| Media generation | Manus task usage plus image, video, voice, or rendering credits. | Set resolution, duration, and monthly budget limits. |
| Automation bridge | Manus usage plus Zapier/Make/n8n operations and target-app charges. | Track each platform’s task/operation quota separately. |

## Security and permission checklist
Before connecting any application, confirm the account or workspace, the exact scopes requested, whether the connector can write or delete, the provider’s data-retention policy, the location where credentials are stored, and the process for revoking access. For APIs, use a dedicated key with the smallest possible scopes and a rotation schedule. For financial, email, social, and production infrastructure connectors, test on a limited account first. Manus states that users can review and revoke access, and that shared sessions redact connector outputs and API keys, but users should still avoid sharing sensitive output in prompts or documents. [2]

## Practical conclusions
The highest-value use of the catalog is multi-application orchestration: research in one system, analysis in Manus, and controlled write-back to another. Airtable, Notion, Google Workspace, GitHub, Slack, HubSpot, Stripe, and the AI-provider connectors are particularly flexible, but they also carry the greatest permission and cost-management responsibility. For a first deployment, enable one read-only connector, test a small workflow, inspect the result, and only then add write scopes or additional connectors.
